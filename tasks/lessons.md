# 經驗迭代與錯誤回顧 (Lessons Learned)

## 核心原則
1. **繁體中文唯一原則**：所有說明、文件、架構圖、註解一律採用標準繁體中文。
2. **圖像與圖表先行**：抽象概念一律搭配 Mermaid 流程圖、架構圖或結構化對比表，避免長篇大論純文字堆砌。
3. **白話生活譬喻 + 法規原意鎖定**：生活化舉例必須精準呼應法條本質（例如：受託人義務、信託財產獨立性防彈衣理論、委託人撤銷權條件），不可因為白話化而犧牲法條要件的嚴謹度。
4. **數字與期間精確性**：信託法規常考天數（例如：公告期間、異議期、申報期限）與金額比例，教材中應有專門的記憶訣竅與彙整表。
5. **單一自包含 HTML 應用架構**：將 Markdown、Mermaid 圖表與真題資料以 JSON 封裝進 HTML，確保使用者在無本機 Web 伺服器的情況下直接點開即可完整預覽，避免任何 CORS 跨域讀取問題。
6. **Mermaid 杜絕紅色炸彈 (Syntax error in text) 的三大鐵律**：
   - 節點標籤只要包含 `?`、`≠`、`:`、`=`、空格等特殊字元，一律必須用雙引號 `["..."]` 包裹。
   - 嚴禁同一節點 ID 同時出現在多個不同的 `subgraph` 內部（會導致 Mermaid lexer 崩潰）。
   - 前端配置 `mermaid.initialize({ suppressErrorRendering: true })`，並使用逐一隔離渲染器（`mermaid.render` 沙箱），保證即使遇到微小語法告警也絕不拋出紅色炸彈，並提供高質感的降級結構卡片。

7. **圖表全面升級為「直接輸出向量圖檔 (SVG)」**：
   - 瀏覽器端執行 Mermaid.js 即時渲染存在中文字元相容性與自動縮小問題，使用者易遇到代碼裸露或字體微小困擾。
   - 將全書所有架構圖與流程圖在後端直接輸出為獨立、標準的 SVG 向量圖檔（儲存於 images/ 目錄），具有深色卡片高對比背景、固定清晰字級（15~18px+）、排版精準。
   - 徹底移除前端 Mermaid.js 腳本依賴，前端改用純淨的高速圖片載入，並搭配「點擊全螢幕燈箱 (Image Lightbox)」互動放大器，兼顧 0 載入延遲、100% 渲染穩定度與極致清晰度。

8. **法規條號必須逐一查證**：引用法規條號（如集合管理辦法 10% 限制實為第 9 條，非第 17 條）不得憑印象填寫，每個條號都要有查證來源。
9. **跨章節題庫需全域去重**：精選題庫除章內不重複外，亦須檢查各章之間 stem 是否重複。
10. **手機端 SVG 向量圖模糊根因與解決準則**：
    - SVG 向量圖在手機上「看似模糊」並非解析度失真，而是原本針對桌面 920px 畫布設計的 14px 字體，被 `max-width: 100%` 硬壓縮至手機 375px 寬度後，等效字級變成 5px，筆劃與像素網格擠壓導致肉眼難以辨識。
    - **解決準則**：在手機端應採用「橫向滑動畫布 (Scrollable Canvas)」模式，設定 `min-width: 760px` 與 `overflow-x: auto`，保障最小字級在手機上仍維持 12px~14px 清晰可讀；搭配全螢幕高清縮放燈箱，提供極致閱讀體驗。
11. **頂部與底部導航按鈕必須做顯式事件綁定**：
    - 頁面上的導航按鈕（如上一章、下一章、速查手冊捷徑）不可遺漏事件監聽器，且測試腳本需模擬點擊測試確保有效觸發。
12. **高頻精選題必須以完整歷屆題庫的知識點頻率為主**：
    - 章末 10 題不得以最新期別或 recent 權重作主排序；先統計第 41–62 期各 topic 的總出題次數，再依高頻主題配置題數，期別僅用來增加跨期代表性。
    - 精選題需保留 frequency、topicRank、frequencyScope 與 source_id，且全章、跨章節 stem 均須去重。
    - 第 08 章為跨章節速查手冊，應由 c01–c07 全題庫的高頻數字／易錯陷阱產生，不使用 c08 舊有 41–43 期切片作為主要來源。
